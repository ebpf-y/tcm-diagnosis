# 中医辨证论治系统

从"体质辨识"升级为"证候级辨证论治"的中医专家系统：
底层保留《中医体质分类与判定》标准（CCMQ-60 量表）的九种体质判定，
上层为**证候辨证层**（八纲/脏腑/气血津液辨证，19 个常见证候），
并为每个证候给出完整调理方案——**经典方剂（组成/剂量/煎服/君臣佐使方解/动态加减/禁忌）、
合方化裁建议、食疗、穴位保健（含标准定位与主配穴）、导引起居**。

通过 **主诉与四诊采集、问卷问诊、AI 对话问诊（选择式）、舌诊拍照、面诊拍照** 五个渠道采集信息，
规则引擎**四诊合参**综合判定体质与证候，方案全部由知识库直接组装（无 LLM 依赖、可解释、可复现）。
另设**复诊复评**模块：初诊/复诊同口径评分对比，判定调理趋势。

> 免责声明：本系统输出为中医辨证调理参考，不构成疾病诊断；方药须在执业中医师指导下使用。

## 核心特性

- **四诊合参**：各渠道体征带来源汇总，同一证候被 ≥2 个渠道支持时互证加分；
  按实际采集类别做覆盖率感知归一（未采集的渠道不稀释得分）；
  渠道间信息矛盾（如畏寒却舌红）显式检出并在报告中提示"待澄清"。
- **方药个体化**：同证多方时按命中体征自动选方排序（如脾气虚兼便溏 → 参苓白术散优先）
  并给出理由；命中体征触发动态加减建议（如兼痰湿 → 加陈皮、半夏）。
- **安全底线**：
  - 禁忌交叉校验——病史/在服药物（识别华法林等）/年龄/当前症状 × 方剂禁忌标签自动匹配，命中即红色警示；
  - 双阈值出方——辨证符合度不足或无主症支持时不出具方药，只出非药物调理；
  - 急重症词条（剧烈胸痛、高热不退等）直接提示就医。
- **脉诊双模式**：业余向导（准备指引 + 60 秒计时计数 + 复测比对 + "不确定不产体征"，
  脉形自评降权 0.5）/ 专家录入（28 脉 + 三部九候矩阵，完整权重参与辨证，
  报告含专家视图：全部候选证候对比）。
- **舌面诊结构化**：多模态模型按固定枚举字段输出（舌色/舌形/苔色/苔质/面色/唇色…），
  确定性映射为体征；先过图像质量门控（光线/滤镜/角度不合格则不产体征、提示重拍）。
- **体质方法论**：体质判定仅以 CCMQ 问卷为准；舌面/对话的体质提示只做一致性校验，不参与计分。
- **君臣佐使结构化方解**：40 首方剂全部按君/臣/佐/使分组标注配伍机理，药味按地位着色。
- **文献考据**：有著录争议的方剂（交泰丸、甘露消毒丹等）附出处考据备注。

## 技术栈

- Next.js 14（App Router）+ TypeScript + Tailwind CSS
- 规则引擎：确定性纯函数（`lib/engine/`），配 vitest 单元测试（110+ 用例）
- LLM 抽象层：OpenAI 兼容协议（`lib/llm/`），默认 DeepSeek（文本）+ 通义 Qwen-VL（图像），
  未配置 Key 时自动进入演示（mock）模式，应用仍可完整跑通
- AI 对话问诊采用选择式交互：LLM 每轮返回 `{reply, options, done}` JSON，
  用户点选候选回答作答；对话结束后 LLM 提取规范化症状关键词，与原文关键词匹配取并集
- Prisma + SQLite：报告与复诊记录持久化（照片不落盘，只存分析文本）

## 快速开始

```bash
npm install          # 安装依赖（自动执行 prisma generate）
npx prisma db push   # 初始化 SQLite 数据库（首次；含 Report / FollowUp 两表）
npm run dev          # 开发模式，访问 http://localhost:3000
```

不配置任何 API Key 也能运行：AI 对话与图像分析将使用内置演示数据。

## 配置 LLM（可选）

复制 `.env.example` 为 `.env`，按需填写：

| 变量 | 说明 | 默认值 |
| --- | --- | --- |
| `LLM_API_KEY` | 文本模型 Key（问诊对话、报告生成） | 空 → 演示模式 |
| `LLM_BASE_URL` | OpenAI 兼容端点 | `https://api.deepseek.com` |
| `LLM_MODEL` | 文本模型名 | `deepseek-chat` |
| `VISION_API_KEY` | 多模态模型 Key（舌诊/面诊） | 空 → 演示模式 |
| `VISION_BASE_URL` | 多模态端点 | 阿里云百炼兼容端点 |
| `VISION_MODEL` | 多模态模型名 | `qwen-vl-max` |
| `DATABASE_URL` | SQLite 连接串 | `file:./dev.db` |

任何 OpenAI 兼容服务均可接入（Kimi、智谱、通义等），示例见 `.env.example`。

## 使用流程

1. **主诉与四诊采集**（/intake）：主诉词条（急重症直接提示就医）、病程、加重/缓解因素、
   既往史与在服药物、生活方式、体检异常、女性/男性专问、脉诊（双模式）、闻诊自评。
2. **问卷问诊**（/questionnaire）：CCMQ-60 标准量表，体质判定的唯一权威渠道。
3. **AI 对话问诊**（/chat）：围绕证候鉴别点的选择式问诊。
4. **舌诊/面诊**（/imaging）：拍照上传，结构化特征提取（含质量门控）。
5. **综合报告**（/report）：四诊合参 → 体质判定 + 证候判定（含命中明细）+
   调理思路（分步先后）+ 方药参考（双阈值/禁忌校验/君臣佐使/动态加减）+
   食疗 + 穴位保健（定位/主配穴）+ 信息矛盾点 + 健康提示。
6. **复诊复评**（/followup）：7~14 天后勾选仍存在的症状与新增不适，
   与初诊同口径对比，给出"好转/平稳/有变化"趋势判定。

## 判定逻辑说明

**体质层（CCMQ 标准）**

1. 问卷渠道严格按 CCMQ 计分：条目 5 级计分（平和质负性条目反向计分）→
   亚量表原始分 → 转化分 `(原始分-条目数)/(条目数×4)×100` →
   按标准阈值判定（偏颇体质 ≥40 为"是"，30~39 为"倾向是"；
   平和质需自身 ≥60 且其余八种均 <30/<40）。
2. **体质判定仅以问卷为准**。舌面/对话渠道的体质提示分不参与计分，
   只做一致性校验：与问卷结论不一致时在报告"信息矛盾点"中提示
   （问卷反映长期体质，舌面象反映当下状态）。

**证候层（四诊合参）**

1. 各渠道命中的体征（`signKeys`，带来源标签）按 **主症 3 分 / 舌脉 2 分 / 兼症 1 分**
   加权汇总（`scorePatterns`）：
   - 以各证候理论满分归一，且只计入**本次实际采集的体征类别**（覆盖率感知归一）；
   - 同一证候被 ≥2 个独立渠道命中 → 互证加成 ×1.2（封顶 100），报告标注"多渠道互证"；
   - 业余自测的脉形体征按 weightScale 0.5 降权；专家模式录入的脉象为完整权重；
   - 排序时**有主症级命中的证候优先**（辨证立证须有主症支持），输出命中明细（可解释）。
2. **双阈值出方**：符合度 ≥40 且有主症级命中才出具方药参考；否则只出食疗/起居/穴位。
3. `buildTreatmentPlan` 组装调理方案：按 favorSigns 选方排序（附理由）、
   modRules 动态加减、兼证合方化裁提示（不另立全方）、病程 >6 个月附"久病入络"提示。
4. 安全校验：`detectConflicts` 信息矛盾检测（含脉症从舍）；
   `checkContraindications` 禁忌交叉校验（病史/在服药/年龄/体征 × 方剂禁忌标签）。
5. LLM 仅撰写"辨证分析"论述段（病机推演、兼证关系、矛盾信息取舍说明）；
   无 Key 时由知识库模板生成。

**复诊层**

初诊与复诊以同一口径（全类别）重跑证候评分：主证符合度下降 ≥30% 判"好转（效不更方）"，
变化 ±30% 内判"平稳"，上升 ≥30% 或主证易位判"有变化（建议重新综合采集或面诊）"。

## 合规说明

- 方药区固定警示条：经典方剂须在执业中医师辨证指导下使用，切勿自行抓药。
- 禁忌交叉校验命中时出具红色警示（病史/在服药物/年龄/当前症状）。
- 孕妇、哺乳期、儿童、慢性病患者提示先经医师面诊；老年/儿童剂量须医师酌减。
- 急重症（剧烈胸痛、高热不退、出血、意识异常等）警示立即就医。
- 脉诊"散脉"等危重脉象附就医提示；专家模式输出明示"辅助参考，处方责任在医师"。
